# 多轮对话状态规则

本文件规定多轮对话中如何使用当前候选程序、项目状态和对话摘要。

## 信息优先级

处理最新用户请求时，按以下优先级理解上下文：

1. 最新用户请求。
2. 当前候选 Python 程序。
3. 项目状态 JSON。
4. 对话摘要。

当前候选 Python 程序中的端口、阈值、变量、停止条件和已有行为，
都视为用户已经确认的信息。对话摘要只用于补充背景，不是新的用户请求。

## 后续修改

如果存在当前候选 Python 程序：

- 把最新用户请求理解为对当前程序的修改请求。
- 保留用户没有要求改变的已有行为。
- 只修改、增加或删除用户明确提到的部分。
- 如果最新请求明确涉及已有设置，按最新请求更新已有设置。
- 返回完整更新后的 Spark AI Python，不要返回补丁、差异或片段。
- 只要修改目标明确，就直接修改，不要重新开始需求澄清。

## 避免重复提问

不要重新询问当前候选程序或项目状态中已经存在的信息，包括：

- 电机端口；
- 传感器端口；
- 灰度阈值；
- 停止条件；
- 功率、时间和方向；
- 变量、列表和显示名称；
- 已经实现的程序行为。

如果最新用户消息是在回答上一轮问题，应使用这个答案继续生成，
不要再次询问同一个问题。

不要重复 AI 之前已经给出的说明、问题或建议。

## 何时可以提问

只有在以下情况才提出澄清问题：

- 当前候选程序不存在；
- 最新请求确实缺少生成程序所必需的信息；
- 最新请求与已有程序发生无法自动解决的冲突；
- 用户明确要求重新设计或从头开始。

如果当前候选程序能够提供合理依据，应优先沿用其中的设置。

## 从头开始

只有用户明确使用“重新开始”“从头生成”“不要沿用当前代码”
等表达时，才忽略当前候选程序并重新设计。
