# Spark AI Python to Blocks

Spark AI Python to Blocks converts the Python dialect generated by Spark AI
back into Spark AI graphical blocks. It can create either a `.sparkai` project
file or Blockly XML that can be copied into the Spark AI workspace.

The tool is intentionally conservative: it only generates blocks that have
been confirmed in the Spark AI interface. Unsupported Python functions or block
shapes fail with an explicit error instead of being guessed.

## What This Project Does

- Converts Spark AI generated Python into a new `.sparkai` file.
- Converts Spark AI generated Python into clipboard XML for direct paste.
- Provides a local web chat flow that can ask DeepSeek to draft Spark AI
  Python, validate it with the converter, and place it into the generation
  text area.
- Preserves mapped display names for variables, lists and custom-block inputs.
- Supports variables, lists, custom blocks, control blocks, operators, motors,
  sensors, matrix display and the built-in buzzer.
- Provides inspection tools for existing `.sparkai` project files.

## Runtime Independence

The converter does not need `Spark-AI.exe` at runtime.

For `.sparkai` output, the converter uses the included fixed template:

```text
templates/base.sparkai
```

The generated `.sparkai` file is still meant to be opened by Spark AI. Hardware
download, execution and debugging still require Spark AI software and hardware.

## Requirements

- Python 3.10 or newer
- No third-party Python package is required for the core CLI, web UI or tests.

The project has been tested on Windows, but the Python code uses only standard
library modules and should also run on macOS and Linux.

## Quick Start

Clone or download the repository.

On Windows, double-click:

```text
Start-SparkAI-Generator.cmd
```

The script starts the local web server and opens:

```text
http://127.0.0.1:8765/generate
```

If double-click launch is blocked by local policy, open PowerShell in the
project directory and run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\start_web.ps1
```

To run tests:

```powershell
python -m unittest discover -s tools -p "test_*.py"
```

Manual web UI start:

```powershell
python tools\sparkai_web.py --host 127.0.0.1 --port 8765
```

In the web UI, you can either:

- describe the hardware program in the AI chat panel, then review the generated
  Python candidate; or
- paste Spark AI Python code into the text area yourself.

After the Python candidate is ready, choose one of:

- `生成剪贴板 XML`: creates one or more XML fragments for copy/paste.
- `生成积木文件`: creates a `.sparkai` file in `generated/`.

The AI chat uses a DeepSeek-compatible API. You can paste the API key into the
page for the current request, or set it before starting the server:

```powershell
$env:DEEPSEEK_API_KEY = "your-api-key"
.\Start-SparkAI-Generator.cmd
```

Do not write real API keys into project files or commit them to Git.

For a private local default key, copy `.env.example` to `.env` and fill in:

```text
DEEPSEEK_API_KEY=your-api-key
```

`.env` is ignored by Git. When the page key field is empty, the web server reads
`.env` first, then falls back to the `DEEPSEEK_API_KEY` environment variable.

## Command Line Usage

Generate a `.sparkai` file from an example:

```powershell
python tools\sparkai_tool.py generate examples\line_follower.py --output generated\line_follower.sparkai
```

Read Python from standard input:

```powershell
Get-Content examples\line_follower.py | python tools\sparkai_tool.py generate - --output generated\line_follower.sparkai
```

Inspect an existing project and regenerate Python:

```powershell
python tools\sparkai_tool.py inspect path\to\project.sparkai
```

Validate an existing project:

```powershell
python tools\sparkai_tool.py validate path\to\project.sparkai
```

Compare a project against reference Python:

```powershell
python tools\sparkai_tool.py compare path\to\project.sparkai examples\line_follower.py
```

## AI Generation

The web UI includes a DeepSeek-compatible AI path. It is not required for the
normal converter: the Python-to-blocks generator still works completely locally.

Set the API key in your current terminal. Do not write the key into Git files.

```powershell
$env:DEEPSEEK_API_KEY = "your-api-key"
```

Ask the AI to generate Spark AI Python and validate it locally from the CLI:

```powershell
python tools\sparkai_ai.py generate "生成一个巡线小车，左右电机接 E/F，左右灰度接 A/B，按 A 口触碰传感器停止，停止后蜂鸣器响一声"
```

The command returns JSON containing:

- `validated`: whether the generated Python passed the local converter
- `validation_error`: converter error text if validation failed
- `repair_attempts`: how many automatic AI repair attempts were used
- `response.python`: the candidate Spark AI Python

The AI rules injected into the request live in [docs/ai_rules](docs/ai_rules).
The model does not read these files by itself; `tools/sparkai_ai.py` reads and
sends them with the API request. The web endpoint `/chat` uses the same AI
module, then returns the validated Python candidate to the page.

## Python Input Format

The input should be the complete Python code copied from the right-side code
area in Spark AI, optionally with mapping comments added near the top.

Variable and list initialization lines are metadata for the compiler. They
create project variables/lists and are not emitted as visible blocks:

```python
Power_ = 0
Speeds_ = PikaStdData.List()

global Power_, Speeds_
```

## Display Name Mapping

Use mapping comments when the Python identifier differs from the visible name
you want in the block workspace.

Recommended long form:

```python
# @sparkai-variable Power_ => 最大功率
# @sparkai-list Speeds_ => 速度列表
```

Short form:

```python
# @var Power_=最大功率
# @list Speeds_=速度列表
```

The web UI shows a mapping summary after generation, including variables or
lists that were not mapped.

## Custom Blocks

Spark AI Python does not contain enough information to recover the visible
template of a custom block. Add comments before the function definition:

```python
# @sparkai-custom sensorDrive => 传感器巡线 左功率 %n 右功率 %n 执行 %b
# @sparkai-custom-arg sensorDrive LeftPower_ => 左功率
# @sparkai-custom-arg sensorDrive RightPower_ => 右功率
# @sparkai-custom-arg sensorDrive Enabled_ => 执行

def sensorDrive(LeftPower_, RightPower_, Enabled_):
    if Enabled_:
        _motor.mov_power(LeftPower_, RightPower_)
```

`%n` creates a numeric input, `%b` creates a boolean input and all other text is
shown as fixed label text on the custom block.

When using clipboard XML, paste custom block definitions first, then paste the
main program stack under the Spark AI start block.

## Supported Scope

The currently supported set includes:

- Combined motor pairing, braking, power, direction, timed movement, offsets
  and line patrol.
- Single motor power, timed movement, stop, brake/coast mode and reset degree.
- Reflected light, grayscale state, ultrasonic value/comparison, touch/key state
  handheld-controller buttons/rocker axes and built-in runtime values such as
  timer and sound intensity.
- Matrix display, clear, scroll text, brightness and single-pixel brightness.
- Built-in buzzer play note and stop.
- `if`, `if/else`, `while True`, `while not`, `for count in range(...)`.
- Wait, stop, arithmetic, comparison, logical, contains, text length, random,
  round and modulo expressions.
- Variables and lists.
- Custom blocks with numeric and boolean inputs.

Known boundary:

- `_color.set_color_threshold_value(...)` is not recommended for current
  generated files because a tested Spark AI version failed to load files
  containing that block. Keep it out until it is revalidated with a newer
  Spark AI release.
- Arbitrary Python is not supported. The input is the Spark AI generated
  Python dialect plus mapping comments.

## Development

See [DEVELOPMENT.md](DEVELOPMENT.md) for the internal architecture, extension
points and release checklist. See [CONTRIBUTING.md](CONTRIBUTING.md) for the
expected process when adding support for new Spark AI blocks.

AI generation rules are kept in [docs/ai_rules](docs/ai_rules). They are
designed to be injected by a backend when calling an AI API; the model will not
read these local files by itself. The rules include a compact hardware overview,
block semantics, supported function list and output protocol.
